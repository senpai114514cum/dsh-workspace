# MinerU 扫描件 OCR 实测 + 同类模型横评

**环境**：MinerU 4.0.11 / MinerU2.5-Pro-2605-1.2B / RTX 3080 Ti 12GB / Windows / LMDeploy TurboMind
**测试时间**：2026-10

---

## 一、扫描件 OCR 实测

### 1.1 为什么用「受控扫描化」而不是下载扫描件

在线扫描件源（archive.org / HathiTrust / Google Books / NASA NTRS / DTIC / Gallica）**在本机网络环境下全部不可达**
（走代理 `127.0.0.1:7890` 也不行；Wikimedia Commons 可直连，但上面的扫描件多为 Internet Archive 上传、
**带 OCR 文字层**，不是真扫描件）。

> Commons 补充测试：搜到 48 个候选，逐一检查文字层后只有 1 个是真正的无文字层扫描件
> （《Soil physics laboratory guide》104 页）。其余都带 IA 的 OCR 文字层。

于是改用**受控扫描化**：把数字版论文用 pypdfium2 渲染成图，再用 Pillow 包成 PDF。
校验确认新 PDF **抽出文字 0 字符** = 真正的无文字层扫描件。

**这条路其实更适合评测**：原始数字版转换结果可以当**标准答案**，
于是能定量算 OCR 准确率，而不是靠肉眼。

### 1.2 测试集

3 篇源论文 × 4 种扫描条件 = **12 个扫描件**（各取前 3 页）：

| 源 | 内容 |
|---|---|
| en-math | 纯数学论文（公式极密，1296 个数学符号） |
| cn-formula | 中文光学论文（公式密集） |
| en-chart | ViT（图表密集） |

| 扫描条件 | 模拟的场景 |
|---|---|
| 300dpi-color | 高质量彩色扫描 |
| 200dpi-gray | 普通灰度扫描 |
| 150dpi-jpeg (q=45) | 低质量 / 强压缩 |
| 300dpi-skew-noise | **倾斜 0.8° + 椒盐噪点**（歪斜进纸、旧纸） |

对照基线：同样三篇论文的前 3 页，走数字版路径（同一条流水线，唯一变量是有无文字层）。

### 1.3 结果

**OCR 分流正确**：12/12 全部被 `auto` 判为 `ocr` ✅
（这批文件抽出文字均为 0-2 字符，分类器准确识别出"无文字层"）

| 扫描条件 | 散文相似度 | 字数保留 | 公式数保留 | 公式有效率 |
|---|---|---|---|---|
| 300dpi-color | **99%** | 99% | 100% | 100% |
| 200dpi-gray | **99%** | 99% | 100% | 100% |
| 150dpi-jpeg | **99%** | 99% | 100% | 100% |
| 300dpi-skew-noise | 98% | 99% | **83%** | 100% |

**公式逐条比对**（模糊匹配，基准 vs 扫描版）：

| 扫描条件 | 完全一致 | 近似(90-99%) | 较差(70-90%) | **丢失(<70%)** |
|---|---|---|---|---|
| en-math / 300dpi-color | 10 | 1 | 1 | **0** |
| en-math / 200dpi-gray | 10 | 1 | 1 | **0** |
| en-math / 150dpi-jpeg | 9 | 2 | 1 | **0** |
| **en-math / 300dpi-skew-noise** | **0** | 6 | 4 | **2** |
| cn-formula / 300dpi-color | 4 | 1 | 1 | **0** |
| cn-formula / 200dpi-gray | 3 | 3 | 0 | **0** |
| cn-formula / 150dpi-jpeg | 0 | 5 | 1 | **0** |
| **cn-formula / 300dpi-skew-noise** | **0** | 2 | 3 | **1** |

「近似」多为 `\left( ... \right)` 与 `( ... )` 这类排版差异，**语义相同**。

### 1.4 结论

1. **干净扫描件（含 150dpi JPEG 压缩）OCR 质量与数字版几乎无差别**：散文 99%、
   公式零丢失、公式语法有效率 100%。MinerU 的 OCR 路径可以放心用。
2. **唯一明显退化是"倾斜 + 噪点"**：公式丢失 2/12（en-math）与 1/6（cn-formula），
   且 12 个公式里没有一个逐字节一致 —— 倾斜改变了 OCR 的读法。
   建议：扫描时保持页面摆正；已歪斜的先用去歪斜工具处理再转。
3. 12 个扫描件**体检全部通过**，没有触发乱码/表格类告警。

## 二、有没有比 MinerU 更强的 OCR 模型？

### 2.1 OmniDocBench v1.6 横评

数据来源：TeleOCR 官方 README 的评测表（使用 OmniDocBench v1.6 官方 Docker 镜像评测）。

| 模型 | 参数 | Overall ↑ | Text Edit ↓ | **Formula CDM ↑** | Table TEDS ↑ | Read Order ↓ |
|---|---|---|---|---|---|---|
| **TeleOCR** | 1.2B | **96.87** | 0.027 | 96.36 | **97.05** | 0.122 |
| OvisOCR2 | 0.8B | 96.58 | **0.025** | **97.53** | 94.76 | **0.111** |
| PaddleOCR-VL-1.6 | 0.9B | 96.33 | 0.033 | 97.49 | 94.76 | 0.127 |
| **MinerU2.5-Pro（当前在用）** | 1.2B | 95.75 | 0.036 | **97.45** | 93.42 | 0.120 |
| GLM-OCR | 0.9B | 95.22 | 0.044 | 97.18 | 92.83 | 0.133 |

**拆开看，结论和总分不一样：**

* **公式**：MinerU2.5-Pro **97.45**，在表中排第一梯队（仅次于 OvisOCR2 的 97.53）。
  TeleOCR 96.36 **反而更低**。
* **表格**：TeleOCR **97.05** vs MinerU 93.42 → **+3.63**，这是 TeleOCR 总分领先的主要来源。
* **文本**：TeleOCR 0.027 优于 MinerU 0.036。
* **阅读顺序**：MinerU 0.120 略优于 TeleOCR 0.122。

### 2.2 拍摄/畸变文档

| 模型 | Dr.DocBench overall ↑ |
|---|---|
| **TeleOCR** | **67.96** |
| MinerU 2.5 Pro | 62.26 |
| OvisOCR2 | 59.25 |
| PaddleOCR-VL 1.6 | 55.11 |

这一项 TeleOCR 领先 **+5.7**，优势明显 —— 但注意**两者的公式分都接近于零**
（TeleOCR 0.02 / MinerU 0.04）：手机拍摄的文档上，公式解析基本失效。

### 2.3 关键的实际障碍：Windows

TeleOCR 官方推理路径**只支持 `vllm-engine` / `vllm-async-engine`**：

```bash
python infer.py --image_sub_path ... --result_save_path ... \
    --override model_path="StarDoc-AI/TeleOCR" BACKEND="vllm-async-engine"
```

**vLLM 没有 Windows wheel** —— 这正是当初装 MinerU 时被迫改用 LMDeploy 的原因。
它另外还依赖 FlashAttention（同为 Windows 老大难）。

要在本机用 TeleOCR，只有三条路：

| 路径 | 代价 |
|---|---|
| WSL2 + vLLM | 需新建 WSL 环境，GPU 直通要配；但可完整复现官方精度 |
| Docker + GPU | 同上，Windows 下 Docker GPU 支持有额外折腾 |
| 社区 GGUF + llama.cpp | 有 Windows 路径，但**量化会掉精度**，多模态支持也较弱 |

### 2.4 结论：**不建议换**

1. **你的核心需求是公式，而 MinerU2.5-Pro 恰好是这一项最强的**（97.45）。
   TeleOCR 总分高 1.12，优势集中在**表格重建**，公式反而低 1.09。
2. **你在干净扫描件上已经接近天花板**：本次实测 OCR 路径的散文保真度 99%、
   公式零丢失、语法有效率 100%。整体分再高 1 分，落到实际文档上的可见提升很小。
3. **迁移成本远大于收益**：要为此搭 WSL2/Docker + vLLM 环境。

### 2.5 什么情况下值得换

| 场景 | 建议 |
|---|---|
| 大量**表格重建**（财报、报表、复杂合并单元格） | 值得评估 TeleOCR —— 表格 TEDS 领先 3.6 |
| **手机拍摄 / 褶皱 / 透视畸变**文档 | TeleOCR 领先 5.7，但公式基本都失效，别指望公式 |
| 当前：学术论文、公式 + 图表、中英文混排 | **保持 MinerU** |

---

## 三、一句话总结

> 扫描件 OCR 这条路 MinerU 已经走通了（干净扫描件 99% 保真、公式零丢失），
> 只有"倾斜 + 噪点"会造成约 8~17% 的公式差异。
> 同量级里确实有总分更高的模型（TeleOCR 96.87 > MinerU 95.75），
> 但它们**在公式这一项上并不更强**，且官方推理依赖 vLLM、没有 Windows 支持。
> **就你的场景而言，没有值得切换的理由。**
